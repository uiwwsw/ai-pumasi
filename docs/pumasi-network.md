# 품앗이 설계

팀 모드에서 작업 모델 자리에 다른 사용자의 앱을 넣는 기능이다. 키와 토큰은 각자 기기에 남는다. 서비스에 키를 올려 나눠 쓰는 방식이 아니다.

## 누가 무엇을 하나

| 단계 | 누가 | 누구의 토큰 |
|---|---|---|
| 나누기 | 올린 사람 앱의 총괄 모델 | 올린 사람 |
| 작업 | 돕는 사람 앱의 자동 (무료) 모델 | 돕는 사람 |
| 고르기 (돕는 사람이 2명 이상일 때) | 올린 사람 앱의 작업 모델 | 올린 사람 |
| 검수·합치기 | 올린 사람 앱 (팀 모드 그대로) | 올린 사람 |

## 흐름

1. **올리기.** 팀 모드가 일을 작업 1~6개로 나누면, 작업마다 자리를 1~3개 연다. 서버에는 작업 크기만 올린다.
2. **돕기.** 돕는 사람이 "돕기"를 누르면 앱이 그 자리만 쓸 일회용 열쇠쌍을 만들고 공개 열쇠를 서버에 맡긴다.
3. **작업 보내기.** 올린 사람의 앱이 그 공개 열쇠로 작업 글을 암호화해 서버에 둔다.
4. **처리.** 돕는 사람의 앱이 메인 프로세스 안에서 작업 글을 풀고, 기부하기로 한 제공자의 키로 자동 라우터를 돌린다. 결과에서 키처럼 보이는 문자열을 가리고, 올린 사람의 작업용 공개 열쇠로 암호화해 서버에 둔다. 작업 글과 결과는 화면(renderer)으로 보내지 않는다. 화면에는 "작업 1건, 토큰 N개"만 보인다.
5. **받기.** 올린 사람의 앱이 결과를 풀어 팀 모드의 검수·합치기로 넘긴다. 같은 작업에 결과가 둘 이상이면 먼저 하나를 고른다. 끝나면 서버에서 그 작업의 암호문을 지운다.
6. **점수.** 돕는 사람은 쓴 토큰만큼 점수를 받고, 올린 사람은 그만큼 쓴다. 가입하면 기본 점수를 받는다.

## 서버가 갖는 것

- 기기 서명 열쇠의 공개 부분(익명 id), 점수 장부
- 자리 상태, 일회용 공개 열쇠, 풀 수 없는 암호문. 암호문은 작업이 끝나거나 1시간이 지나면 지운다.

모든 요청은 기기 서명 열쇠로 서명하고, 서버는 서명과 시각을 확인한다.

## 지킬 수 있는 것과 없는 것

- 돕는 사람은 앱 화면에서 작업 글과 결과를 볼 수 없다. 서버 운영자도 볼 수 없다.
- 앱은 오픈소스이고 돕는 사람의 컴퓨터에서 돈다. 고친 앱을 만들면 볼 수 있다. AI 제공자도 글을 본다. 그래서 올리기 전에 이메일·전화번호·키처럼 보이는 문자열이 있으면 막고, 개인 정보나 회사 자료는 올리지 말라고 안내한다.
- 고친 앱은 엉터리 결과를 돌려줄 수 있다. 작업마다 돕는 사람을 2명 두면 올린 사람의 앱이 비교해 고르고, 총괄 모델 검수가 한 번 더 거른다.
- 앱의 AI에는 파일·셸·브라우저 권한이 없다. 악의적인 작업이 와도 모델에게 보내는 글일 뿐이고, 모델은 키를 모른다.

## 돕는 사람이 정하는 것

- 기부할 제공자 (기본 모두 꺼짐). 그 제공자의 약관이 다른 사람의 요청 처리를 허용하는지 확인하라고 안내한다.
- 하루 기부 한도 (토큰)

## 단계

1. 수동 "돕기", 초대 코드 가입, 작업당 돕는 사람 1~3명, 점수 장부
2. 자동 돕기, 신고·차단
3. 공개 가입

## 정하지 않은 것

- 제공자마다 다른 토큰 값을 점수에 어떻게 반영할지
- 서버를 공개로 열 시점과 운영 비용

# 품앗이 게시판 설계 (다음 기능)

품앗이 에이전트의 다음 기능이다. 지금의 앱(혼자 쓰기)은 그대로 두고, 그 위에 "내 토큰을 빌려주고, 남의 토큰을 빌려 쓰는" 게시판을 더한다.

## 한 줄 요약

문제를 올리면 내 앱이 일을 작게 나눠 게시판에 건다. 다른 사용자가 "돕기"를 누르면 **그 사람의 앱이 자기 키와 토큰으로** 작은 일 하나를 자동으로 처리해 결과를 올린다. 사람이 대신 풀지 않는다. 돕는 사람은 토큰을 기부할 뿐이다. 여러 결과는 지금 앱의 투표·검산 로직으로 고르고, 올린 사람의 앱이 하나로 합친다.

## 두 가지 쓰는 방식

| 방식 | 누가 토큰을 쓰나 | 지금 상태 |
|---|---|---|
| 혼자 쓰기 | 나 | 있음 (단일 모델, 팀 모드, 묶음 투표, 자동 라우터) |
| 게시판에 올리기 | 돕는 사람들 | 이 문서 |

## 흐름

1. **올리기.** 올린 사람의 앱이 팀 모드의 나누기 단계로 문제를 서로 독립적인 작업 1~6개로 나눈다. 각 작업은 그것만 보고 풀 수 있게 필요한 내용을 모두 담는다. 원문 전체는 서버에 올리지 않고 작업 단위로만 올린다.
2. **돕기.** 돕는 사람이 목록에서 "돕기"를 누르거나 "자동 돕기"를 켜 둔다. 앱이 작업 하나를 받아 자기 키로 자동 라우터를 돌리고, 결과 글만 서버에 올린다. 키는 그 기기를 떠나지 않는다.
3. **교차 확인.** 작업 하나를 서로 다른 사람 2~3명에게 준다. 짧은 정답이 있는 작업은 투표와 조기 확정으로, 서술형은 가장 믿을 만한 결과를 바탕으로 합친다. 한 사람이 엉터리 결과를 올려도 걸러진다.
4. **합치기.** 작업이 모두 정해지면 올린 사람의 앱이 결과를 하나로 합친다. 합치기는 올린 사람의 토큰으로 한다.
5. **주고받기.** 기부한 만큼 점수가 쌓이고, 문제를 올릴 때 점수를 쓴다. 점수는 실제로 쓴 토큰 수(제공자가 알려 준 사용량)를 기준으로 한다.

## 돕는 사람이 정하는 것

- 기부 한도: 하루 최대 토큰, 작업당 최대 토큰
- 기부할 키: 제공자별로 켜고 끄기. 약관상 허용된 제공자만 켤 수 있다(아래).
- 자동 돕기: 켜 두면 앱이 쉬는 동안 알아서 처리한다. 노트북 전원·요금제 상황을 보고 멈출 수 있다.
- 받지 않을 작업 종류

## 안전과 개인정보

- **돕는 사람의 기기:** 받은 작업은 모델에게 보내는 글일 뿐이다. 앱의 AI에는 파일·셸·브라우저 권한이 없으므로, 악의적인 작업이 와도 돕는 사람의 파일이나 키에 닿지 못한다. 결과는 키 가리기(`redact`)를 거쳐 올린다.
- **올리는 사람의 내용:** 모르는 사람의 AI가 작업 내용을 본다. 올리기 전에 경고하고, 이메일·전화번호·키처럼 보이는 문자열은 올리기 전에 막는다. 회사 자료는 올리지 말라고 안내한다.
- **악용:** 신고, 차단, 사용자별 올리기 한도. 해로운 요청은 서버에서 거절한다.
- **서버가 갖는 것:** 작업 글, 결과 글, 익명 사용자 id, 점수 장부. 키와 원문 전체는 갖지 않는다.

## 제공자 약관 (출시 전 확인 필수)

"내 키로 남의 요청을 처리"가 허용되는지 제공자마다 확인하고, 허용된 곳만 기부 대상으로 켠다.

- 유료 API(OpenAI, Anthropic 등): 대체로 자기 서비스로 다른 사람의 요청을 처리하는 것을 허용한다. 약관 원문으로 다시 확인한다.
- 무료 체험·무료 한도(NVIDIA 체험, Gemini 무료 한도 등): "개인 개발·평가용" 조건이 있을 수 있다. 허용되지 않으면 기부 대상에서 뺀다.
- 한 제공자에 여러 계정을 만들어 한도를 늘리는 방식은 어떤 경우에도 지원하지 않는다.

## 구성

| 부분 | 내용 |
|---|---|
| 서버 | 작업 게시·배정·결과 수집·점수 장부. Mac mini 운영 환경에 올린다. 작은 API와 데이터베이스 하나. |
| 앱: 올리기 | 팀 모드 나누기 재사용, 작업 게시, 진행 표시, 결과 합치기 |
| 앱: 돕기 | 작업 받기, 자동 라우터로 처리, 키 가리기 후 결과 올리기, 기부 한도 |
| 앱: 고르기 | 묶음 투표(조기 확정), 검산 선택 재사용 |
| 계정 | 처음에는 기기별 익명 id와 서명 키. 점수 이전이 필요해지면 로그인 추가 |

## 단계

1. **MVP:** 정답이 프로그램으로 확인되는 작업(계산, 퍼즐)만 받는다. 올리기 → 돕기(수동 버튼) → 2~3명 교차 확인 → 점수. 서버는 초대한 사용자만.
2. **개발 게시판:** 코드 작업을 받는다. 결과 고르기는 교차 투표와 합치기로 한다. 앱에는 코드 실행 권한이 없으므로 테스트 실행은 올린 사람이 한다.
3. **자동 돕기와 공개:** 자동 돕기, 신고·차단, 공개 가입.

## 정하지 않은 것

- 점수의 단위와 환산(제공자마다 토큰 값이 다르다)
- 돕는 사람이 결과를 올리기 전에 내용을 볼지
- 서버를 공개로 열 시점과 운영 비용
